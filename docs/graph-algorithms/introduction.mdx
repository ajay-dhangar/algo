# 📚 Graph Fundamentals & Representations

A **Graph** is a non-linear data structure consisting of a set of **Vertices (Nodes)** and a set of **Edges** connecting pairs of vertices. Graphs model complex real-world relationships such as social networks, transportation systems, computer networks, and dependency graphs.

---

## 🔑 Key Graph Terminology

| Term | Definition |
| :--- | :--- |
| **Vertex (Node)** | An individual data point or entity in a graph ($V$). |
| **Edge (Link)** | A connection between two vertices ($E$). |
| **Degree** | The number of edges connected to a vertex. For directed graphs: **In-degree** (incoming) and **Out-degree** (outgoing). |
| **Path** | A sequence of vertices where each adjacent pair is connected by an edge. |
| **Cycle** | A path that starts and ends at the same vertex with no repeated edges. |
| **Connected Component** | A maximal subgraph in which any two vertices are reachable from each other. |

---

## 🌐 Graph Classifications

```
                          Graph Types
                        /             \
             Directed (Digraph)     Undirected
                /         \
          Weighted      Unweighted
            /                \
        Cyclic              Acyclic (DAG)
```

1. **Directed vs. Undirected**:
   - **Undirected**: Edges are bidirectional ($(u, v) = (v, u)$).
   - **Directed (Digraph)**: Edges have orientation ($(u \rightarrow v) \neq (v \rightarrow u)$).
2. **Weighted vs. Unweighted**:
   - **Weighted**: Edges carry numerical costs, distances, or capacities.
   - **Unweighted**: All edges have equal unit weight.
3. **Cyclic vs. Acyclic**:
   - **Cyclic**: Contains at least one cycle.
   - **Acyclic**: Contains no cycles. A **Directed Acyclic Graph (DAG)** is essential for topological sorting.

## 💾 Graph Representations

Depending on graph density ($E \approx V^2$ for dense vs $E \approx V$ for sparse), choose the appropriate representation:

### 1. Adjacency Matrix
An $V \times V$ 2D matrix where `matrix[i][j]` represents the weight of edge $i \rightarrow j$ (or $1$ if present).

- **Pros**: $O(1)$ edge lookup time.
- **Cons**: $O(V^2)$ memory storage.

```cpp
// C++ Adjacency Matrix Initialization
int V = 4;
vector<vector<int>> adjMatrix(V, vector<int>(V, 0));
adjMatrix[0][1] = 1; // Edge 0 -> 1
adjMatrix[1][2] = 5; // Edge 1 -> 2 with weight 5
```

### 2. Adjacency List
An array of lists or vectors where `adj[i]` contains all neighbors of vertex $i$.

- **Pros**: Optimal space $O(V + E)$, fast neighbor iteration.
- **Cons**: $O(\text{degree}(v))$ edge lookup time.

```python
# Python Adjacency List
graph = {
    0: [(1, 2), (2, 4)],  # (neighbor, weight)
    1: [(2, 1), (3, 7)],
    2: [(3, 3)],
    3: []
}
```

### 3. Edge List
An array containing all edge tuples `(u, v, weight)`.

- **Pros**: Compact for algorithms that iterate directly over edges (e.g. Kruskal's MST, Bellman-Ford).
- **Cons**: $O(E)$ time to find adjacent vertices of a node.

---

## 📊 Representation Comparison

| Property | Adjacency Matrix | Adjacency List | Edge List |
| :--- | :--- | :--- | :--- |
| **Space Complexity** | $O(V^2)$ | $O(V + E)$ | $O(E)$ |
| **Add Edge** | $O(1)$ | $O(1)$ | $O(1)$ |
| **Remove Edge** | $O(1)$ | $O(\text{degree}(v))$ | $O(E)$ |
| **Check Edge $(u, v)$** | $O(1)$ | $O(\text{degree}(u))$ | $O(E)$ |
| **Best For** | Dense Graphs ($E \approx V^2$) | Sparse Graphs ($E \ll V^2$) | Edge-centric algorithms (Kruskal) |
